    Checks overview

    amlint's checks catch Alertmanager config mistakes that lose alerts, send them to the wrong place, or mute them when they shouldn't be.

    amlint has 38 checks. amtool check-config also catches 20 of them: Alertmanager refuses to load those configs, and amlint reports them so one run covers everything. The other 18 are configs that amtool accepts and Alertmanager runs, just not the way you meant. Those are the main reason to run amlint.

    The three Prometheus rules checks run only with amlint check --rules, which compares your routes and inhibition rules with the alerts your Prometheus rule files define. See Prometheus rules.

    From the CLI, amlint list prints the same list, and amlint explain <code> explains one check.

    All checks

    Grouped by page, then by level. ✓ in the amtool column means amtool check-config catches it too.

    area check level amtool what it flags
    Routing no-root-route error ✓ The config has no route: key.
    Routing invalid-root-route error ✓ The root route has no receiver, or has matchers, continue: true or time intervals.
    Routing undefined-receiver error ✓ A route names a receiver that isn't defined in receivers:.
    Routing groupby-ellipsis error ✓ group_by lists '...' next to label names.
    Routing bad-regex error ✓ A regex doesn't compile, or uses syntax Go RE2 doesn't support, like lookahead.
    Routing bad-matcher error ✓ A matchers: entry Alertmanager can't parse.
    Routing bad-match-label error ✓ A match: or match_re: key that isn't a classic label name, like k8s.ns.
    Routing unreachable-route warn A catch-all route without continue: true hides the sibling routes after it.
    Routing route-match-collision warn Two sibling routes have identical matchers; the second never gets alerts.
    Routing shadowed-route warn An earlier sibling route matches every alert this route matches; this one never gets alerts.
    Routing stripped-brace warn A bare matcher value ends in }, which Alertmanager strips off.
    Routing useless-continue info continue: true on the last sibling route does nothing.
    Routing deep-nesting info The routing tree is more than 5 levels deep.
    Receivers duplicate-receiver error ✓ Two receivers share the same name.
    Receivers email-no-smarthost error ✓ An email_configs entry has no smarthost, and global.smtp_smarthost isn't set.
    Receivers webhook-no-url error ✓ A webhook_configs entry has no url or url_file.
    Receivers pagerduty-no-routing-key error ✓ A pagerduty_configs entry has no routing_key or service_key (or their _file forms).
    Receivers slack-no-api-url error ✓ A slack_configs entry has no api_url, and global.slack_api_url isn't set.
    Receivers opsgenie-no-api-key error ✓ An opsgenie_configs entry has no api_key, and global.opsgenie_api_key isn't set.
    Receivers msteams-no-webhook-url error ✓ An msteams_configs entry has no webhook_url or webhook_url_file.
    Receivers telegram-no-bot-token error ✓ A telegram_configs entry has no bot_token or bot_token_file.
    Receivers discord-no-webhook-url error ✓ A discord_configs entry has no webhook_url or webhook_url_file.
    Receivers victorops-no-api-key error ✓ A victorops_configs entry has no api_key, and global.victorops_api_key isn't set.
    Receivers wechat-no-corp-id error ✓ A wechat_configs entry has no corp_id, and global.wechat_api_corp_id isn't set.
    Receivers sns-no-target error ✓ An sns_configs entry has none of topic_arn, phone_number or target_arn.
    Receivers template-file-missing error A relative templates: path matches no file next to the config (warn for a glob).
    Receivers empty-receiver warn A receiver has no integration, like slack_configs (info for the root route's receiver or one named like null).
    Receivers unused-receiver info A receiver no route uses.
    Inhibition inhibit-no-equal warn An inhibition rule has no equal: field.
    Inhibition circular-inhibition warn Two inhibition rules can mute each other.
    Inhibition inhibit-same-match info The source and target side of an inhibition rule share a label="value".
    Timing undefined-time-interval error ✓ mute_time_intervals or active_time_intervals names an interval that isn't defined.
    Timing repeat-before-group warn repeat_interval is shorter than group_interval.
    Timing wait-exceeds-interval warn group_wait is longer than group_interval.
    Timing global-resolve-timeout-missing info global.resolve_timeout isn't set, so Alertmanager uses its default of 5m.
    Prometheus rules route-unknown-alertname warn With --rules: a route matches an alertname no alerting rule produces.
    Prometheus rules inhibit-unknown-alertname warn With --rules: an inhibition rule's source or target matches an alertname no alerting rule produces.
    Prometheus rules alert-hits-default-receiver info With --rules: alerts match no child route, by their static labels, and go to the root route's receiver.

    Severity levels

    level meaning
    error Alertmanager refuses the config, or notifications can't be delivered as configured.
    warn The config loads, but almost certainly doesn't do what you meant.
    info Worth a look. Often intentional.

    amlint check exits 1 on an error finding. Warnings fail it only with --strict. See exit codes.

    Ignoring checks

    For a whole repo: list checks to skip, or change a check's level, in .amlint.yml in the directory you run amlint from ([tool.amlint] in pyproject.toml works too). See project config.

    .amlint.yml
    ignore:
  - unused-receiver
severity:
  empty-receiver: info       # warn → info
  deep-nesting: warn         # info → warn

    For one run: amlint check alertmanager.yml --ignore deep-nesting,unused-receiver, or --only bad-regex to show nothing else.

    For one spot in the config: add a comment, so the exception and its reason sit next to the config. See inline suppressions.

    # amlint: disable-file=global-resolve-timeout-missing

route:
  receiver: default
  routes:
    - receiver: catch-all   # amlint: disable=unreachable-route
    - matchers: [team="infra"]
      receiver: infra
    • # amlint: disable=<code>,<code> at the end of a line silences those checks on that line.
    • The same comment on a line of its own silences them on the next line of YAML.
    • # amlint: disable-file=<code>,<code> in the comment block at the top of the file, before any YAML, silences them for the whole file.

    A finding's line is the one amlint prints with it.
